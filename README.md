# dming

课堂随机点名器。单文件 C 程序，把名单渲染成一个自包含的网页，在本机 `127.0.0.1` 上起一个只读页面服务，然后用默认浏览器打开。

点名进度（哪些人已经点过）存在浏览器里，按「页面地址」区分。所以端口是固定的。

## 编译

Windows（MinGW-w64 / clang）：

```
build.bat
```

其它平台：

```
./build.sh            # 产物在 dist/
```

Windows 需要链接 `-lws2_32`，两个脚本都已带好。

## 数据文件

放在**程序所在目录**（不是当前目录）：

- `p.txt`：每行一个学生姓名
- `class.txt`：班级名称，取第一个非空行

## 用法

```
dming                       # 起服务并打开浏览器（默认 http://127.0.0.1:47123/）
dming -no-open              # 只起服务，不打开浏览器
dming -port 47124           # 换端口（换端口会让上次的点名记录失联）
dming -heartbeat 5m         # 页面心跳断了 5 分钟就停止服务（默认 5m，0 表示一直服务）
dming -state-ttl 45m        # 上次点名记录的有效期（默认 7 分钟）
dming -quiet                # 只输出页面地址
```

打开着的页面每 30 秒向服务发一次心跳（`GET /__ping`）。心跳断掉 5 分钟后服务自己退出，所以不用管它会不会常驻；页面还开着服务就还在。

页面还在、服务已经没了（比如笔记本睡了一觉把定时器挂起），页面会弹一次「本地服务已停止」的提示；进度本身还在浏览器里，重新运行程序再刷新就能接着点。窗口关掉（或 Ctrl+C）则立即停止。

## 为什么是本地服务，不是 file://

进度用的是 `localStorage`，而 `localStorage` 按 origin 隔离：

- `file://` 下各浏览器行为不一致：Chromium 把整个 `file://` 当一个 origin，Firefox 把每个文件当独立 origin（3.5.x 的固定文件名就是在绕这个）。
- `http://127.0.0.1:<端口>/` 是所有内核都认的稳定 origin。

代价是**端口必须固定**——端口一变，origin 就变，进度等于从头开始。这也是「第二个实例复用第一个实例」存在的原因：端口已被占用、且对方服务的是同一个页面文件时，新实例不另起服务，直接把浏览器指过去，所以随手重复启动不会丢记录。

只监听 loopback，不对外开放，也不会触发防火墙授权。

## 从 3.5.x 升级

- 页面地址从 `file:///.../DMING.html` 变成了 `http://127.0.0.1:47123/`，**旧的点名记录不会带过来**（origin 变了），升级后第一次运行是全新进度。
- `-delay` / `-keep` 已废弃：页面不再自动删除，`DMING.html` 留在程序目录（已在 `.gitignore` 里）。
- `-no-open` 的含义从「只生成 HTML」变成「起服务但不打开浏览器」。
- 服务不再是「没人访问才停」，而是跟着页面的心跳走：页面一关，5 分钟后自动停。
